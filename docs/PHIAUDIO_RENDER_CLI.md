# phiaudio-render CLI Qualification

This rung gives WaveForgeStudio's planned PHIAudio runtime contract an actual local command surface.

## Command

```bash
phiaudio-render \
  --bundle phiaudio/phiaudio_bundle.json \
  --out render/phiaudio \
  --enable-phiaudio
```

Optional sample rates are 44100, 48000, or 96000 Hz.

## Operator gate

Rendering fails unless `--enable-phiaudio` is present. This matches WaveForgeStudio's current adapter contract, which requires explicit operator enablement.

## Path safety

The output root must be relative and may not traverse with `..`.

Stem IDs are converted to safe filename components, and filename collisions after sanitization are rejected.

## Cross-language bundle verification

WaveForgeStudio calculates `bundle_hash` using Python's canonical JSON representation. Python preserves float identity such as `0.0`, while normal JavaScript parsing converts that value to the number `0`.

Therefore PHIAudio verifies file-based WaveForge bundles with a lexical JSON canonicalizer that:

- sorts object keys,
- removes the top-level `receipt` from the hashed body,
- preserves serialized number tokens such as `0.0` and `1.0`,
- decodes strings before canonical UTF-8 serialization,
- hashes the canonical bytes with SHA-256.

A regression fixture is pinned to a digest generated by WaveForgeStudio-compatible Python canonicalization.

## Outputs

The CLI writes:

- `master.wav`
- `stems/<stem>.wav`
- `phiaudio_render_manifest.json`
- `phiaudio_render_receipt.json`

No network access is used.
