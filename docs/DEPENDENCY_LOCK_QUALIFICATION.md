# Dependency Lock Qualification

PHIAudio now commits `package-lock.json` and installs dependencies with `npm ci`.

## Why this matters

WaveForgeStudio's runtime attestation previously detected that PHIAudio had no committed dependency lock. That meant the Git source tree was pinned, but npm could still resolve newer dependency versions inside the allowed semver ranges.

This rung closes that gap.

## CI guarantees

Every PHIAudio pull request now:

1. installs exactly from the committed npm lock with `npm ci`,
2. regenerates lock metadata using `npm install --package-lock-only --ignore-scripts`,
3. requires that regeneration to produce no `package-lock.json` diff,
4. typechecks,
5. runs the full deterministic audio test suite.

The lock was generated by npm on Node 22 and committed unchanged.

## Current locked development graph

The lock records exact resolved versions and integrity hashes for the TypeScript toolchain, including transitive packages. Future dependency changes must intentionally update the committed lock.

## Downstream effect

A future WaveForgeStudio runtime-lock update can qualify this PHIAudio revision and require:

`dependency_lock_tracked=true`

instead of carrying the previous `no_committed_dependency_lock` warning.
